# Portfolio beta publication

CareerPilot's public-facing documentation describes a beta for individual local
use. It is not a hosted service or a promise of automated applications on every
job site. The interface is currently Turkish; the main README is English, with
a linked Turkish overview and daily-use guide.

## Reuse decision

The maintainer chose portfolio presentation without an open-source licence.
`UNLICENSED` in package metadata records this decision; no MIT or other
open-source licence has been added. Dependency licences are separate.
GitHub visibility and the permissions granted by its terms are separate from
project licensing. Public copies cannot be recalled by making the repo private.
See [GitHub's licensing guide](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

## Before changing visibility

- Review the README, beta limitations and fictional screenshots.
- Review reachable Git history for credentials and personal information, including
  commit author/committer metadata. A pattern scan is not a complete audit.
- Review PR/issue bodies, reviews, comments, releases, attachments and any Actions
  logs/artifacts. Checks of local files do not cover these automatically.
- Confirm that copied third-party code/assets, if any, have compatible permission
  and required attribution. An absent attribution is not proof of original code.
- Keep private profile/CV/state files and credentials out of every published ref.
- Confirm that revealing the source and history is intentional. Do not publish
  the real local dashboard or enable public access to personal application data.

The repository owner makes the visibility change separately. These notes and
the `UNLICENSED` marker do not switch a repository to public or grant an open-source
licence. Changes to visibility should follow an explicit review of the exact repo.
